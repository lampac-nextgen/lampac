# DatabaseEditor

Защищённый root-паролем WebLog редактор баз `database/TimeCode.sql` и
`database/Sync.sql`.

## Маршруты

- `/database-editor` — интерфейс редактора.
- `/database-editor/api/summary` — состояние и размер баз.
- `/database-editor/api/records` — поиск и постраничный список; Sync сгруппирован по пользователям, TimeCode показан по записям.
- `/database-editor/api/record` — чтение одного таймкода в формате road JSON Lampa.
- `/database-editor/api/sync-user` — карточки и категории одного Sync-пользователя.
- `/database-editor/api/sync-item/save` — точечное изменение категорий карточки Sync.
- `/database-editor/api/sync-item/delete` — снятие карточки из всех категорий Sync с сохранением отметки удаления для синхронизации.
- `/database-editor/api/save` — создание или изменение таймкода.
- `/database-editor/api/delete` — снятие таймкода с сохранением отметки удаления для синхронизации.
- `/database-editor/api/user-areas` — имена областей данных из обеих баз, включая пользователей только с отметками удаления.
- `/database-editor/api/rename-user` — атомарное переименование пользователя во всех строках `bookmarks` (Sync) и `timecodes` (TimeCode).
- `/database-editor/api/merge-users/preview` — предварительная проверка объединения двух пользователей и подсчёт результата без изменения баз.
- `/database-editor/api/merge-users` — объединение обеих областей данных после проверки с автоматическими копиями обеих баз.
- `/database-editor/api/delete-user` — атомарное удаление пользователя и всех его строк из `bookmarks` (Sync) и `timecodes` (TimeCode).
- `/database-editor/api/backup` — online-backup одной базы или обеих баз при
  `database: "all"` в `database/backup/database-editor`.
- `/database-editor/api/backups` — список доступных резервных копий выбранной базы.
- `/database-editor/api/restore` — проверка и восстановление выбранной SQLite-копии; перед заменой автоматически создаётся страховочная копия текущей базы с маркером `before-restore`.

Изменяющие запросы требуют заголовок `X-Database-Editor: 1`. Все SQL-запросы
параметризованы; изменения синхронизируются семафорами `TimeCode:<user>` и
`Sync:<user>`. Для совместимости со старыми маршрутами Sync редактор также
берёт глобальную блокировку. При переносе записи или переименовании
блокируются оба имени пользователя. В корне поля `data` допускается только JSON-объект. Список TimeCode
дополняется названиями и постерами из карточек Sync того же пользователя.

Редактор Sync повторяет категории Lampa: `book` (Закладки), `like` (Нравится),
`wath` (Позже), `history` (История просмотров). Поле `wath` является актуальным
именем Lampa, несмотря на опечатку в английском ключе. Статусы `look` (Смотрю),
`viewed`, `scheduled`, `continued`, `thrown` взаимоисключающие. Служебное поле
`watch` сохраняется в поддерживаемой схеме Lampac, но в редакторе не выводится.

Мод также добавляет вкладку `Databases` в `/weblog` на лету, не изменяя файлы
штатного модуля WebLog.

## Совместимость с актуальной схемой Lampac

Sync хранит одну строку на карточку: `card_id`, JSON `card`, JSON-карту
`categories`, `changed_at` и `updated_at`. Редактор меняет только выбранную
карточку, сохраняет неизвестные категории и скрытое поле `watch`.
Редактирование прежнего JSON всего пользователя недоступно в этой схеме.

TimeCode хранит позицию, длительность, процент, профиль, нативный `identity`,
`watched_at`, `updated_at`, `extra` и `deleted` в отдельных столбцах.
Редактор собирает и принимает road JSON Lampa: `time`, `duration`, `percent`,
`profile`, `updated` и необязательный `id`. Дополнительные поля сохраняются
в `extra`. Для нативной записи с `id` поле hash можно оставить пустым.

Каждая правка и удаление поднимает `updated_at` выше курсора пользователя,
чтобы клиент получил дельту. При удалении одной карточки или таймкода строка
остаётся в базе как отметка удаления и скрывается из списков редактора.
Удаление пользователя по-прежнему полностью удаляет все его строки.
Переименование изменяет только имя области данных и сохраняет даты записей;
учётные записи и профили Lampa/AccsDB редактируются отдельно.

## Переименование и объединение пользователей

Имена областей данных учитываются точно, включая регистр: `user` и `User`
могут быть разными пользователями в существующей базе. Переименование не
объединяет их: занятое итоговое имя отклоняется, в том числе при совпадении
без учёта регистра. Проверка занятости исключает только точное исходное имя.
Список для этих операций включает также пользователей, у которых остались
только отметки удаления.

Кнопка «Объединить пользователей» позволяет выбрать два исходных имени и
необязательное итоговое имя. Если поле пустое, сохраняется имя второго
пользователя. Можно оставить любое из двух исходных имён или указать новое
незанятое; данные третьего пользователя автоматически не присоединяются.

Карточки Sync объединяются по `card_id`, категории складываются с сохранением
самой свежей даты каждой категории. Для взаимоисключающих статусов остаётся
один с самой свежей датой; неизвестные категории и `watch` сохраняются.
При совпадении таймкодов активная запись имеет преимущество перед отметкой
удаления; среди активных выбирается последняя по `watched_at`, затем по
`updated_at`. Позиция, процент и профиль берутся из неё. Дополнительные поля
карточек и `extra` дополняются из другой записи без замены выбранных значений.
Разные нативные `identity` сохраняются даже при совпадении hash; конфликтующий
hash снимается у нативной записи, которая остаётся доступна через `identity`.
Курсоры результата повышаются, чтобы клиенты получили объединённые данные.

Сначала нажмите «Проверить результат»: редактор покажет итоговое имя,
количество записей и совпадений. Выполнение разрешено только для проверенных
данных; если они изменились, нужна новая проверка. Перед изменением создаются
копии TimeCode и Sync в `database/backup/database-editor` с маркером
`before-merge`. Изменения обеих баз выполняются одной транзакцией.

Перед переименованием или объединением выйдите из исходных пользователей
на всех устройствах и затем используйте итоговое имя в Lampa. Открытые
клиенты со старым `account_email` могут создать старые области заново.
Учётные записи и настройки init/AccsDB автоматически не меняются.

## Резервные копии и установка

Перед восстановлением проверяются целостность SQLite и столбцы текущей схемы.
Копии старого формата с `data`/`updated` отклоняются до изменения базы.
Миграцию старых баз выполняют штатные модули Lampac при запуске; редактор
самостоятельно схему не меняет. Для восстановления полной копии рекомендуется
остановить синхронизацию клиентов на время операции.

Интерфейс включает светлую и тёмную темы, адаптивную сетку карточек,
источник каталога и прокрутку к списку при переходе между страницами.
Дополнительные персональные модули для его работы не требуются.

После обновления C#-файлов перезапустите Lampac для загрузки новой версии модуля.
