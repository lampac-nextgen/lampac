**Экран входа с QR-кодом и Telegram-бот для [Lampac NextGen](https://github.com/lampac-nextgen/lampac)**

## ✨ Возможности

- 📱 **Вход по QR** - наводите камеру телефона на экран ТВ, жмёте «Подтвердить» в боте, и телевизор входит сам.
- 🙋 **Заявки на доступ** - новый пользователь нажимает «Запросить доступ», админ одобряет одной кнопкой, и та же сессия сразу входит без пароля.
- 👥 **Управление из Telegram** - `/users`: список пользователей, карточки, бан и разбан, статистика.
- 🖥️ **Один аккаунт - много устройств** - один пароль работает на ТВ, телефоне и в браузере одновременно.
- 🎬 **Красивый экран входа** - стена постеров в стиле Netflix, «стеклянные» кнопки, свой вид для ТВ, компьютера и телефона.
- ⚡ **Лёгкий для слабых ТВ** - фон собирается на сервере в одну картинку, телевизору почти нечего считать.

## 🚀 Быстрый старт

**1. Включите модуль** - в `Modules/Community/QRAuth/manifest.json` поставьте `"enable": true` и уберите `QRAuth` из `BaseModule.SkipModules` (в `base.conf` модуль в SkipModules по умолчанию).

Собирать ничего не нужно: Roslyn компилирует `.cs` на лету, а `Telegram.Bot.dll` уже лежит в `references/`.

**2. Включите `accsdb` в `init.conf`** - это авторизация самого Lampac, модуль работает поверх неё:

```json
"accsdb": {
  "enable": true,
  "whitepattern": "^/adminpanel",
  "shared_passwd": "длинный_случайный_пароль",
  "accounts": {},
  "users": []
}
```

**3. Добавьте секции модуля** (все поля - в [`init.merge.example.json`](init.merge.example.json)):

```json
"QRAuthBot": {
  "enable": true,
  "bot_token": "123456:ABC-DEF...",
  "admin_ids": [123456789]
},
"DenyPage": {
  "tg_target": "@YourBot",
  "show_qr": true,
  "page_title": "Вход в Lampa",
  "page_subtitle": "Войдите через Telegram или по паролю."
}
```

> [!TIP]
> Токен бота выдаёт [@BotFather](https://t.me/BotFather) (`/newbot`), свой Telegram ID для `admin_ids` покажет [@userinfobot](https://t.me/userinfobot).

> [!WARNING]
> **Для QRAuth нужен отдельный бот.** Если рядом стоит модуль [SeriesNotify](../../SeriesNotify) (секция `SeriesNotify`), у `QRAuthBot` и `SeriesNotify` должны быть **разные** `bot_token`. `DenyPage.tg_target` должен указывать на бот из `QRAuthBot`.

<details>
<summary>❓ <b>Почему нельзя один токен на оба модуля</b></summary>

<br>

Оба модуля получают события от Telegram через long polling (`GetUpdates`), и каждый опрашивает Telegram сам. Общего обработчика, который раздавал бы события обоим модулям, нет.

1. **Один токен - один активный `GetUpdates`.** Если два процесса опрашивают один токен, Telegram отвечает `409 Conflict: terminated by other getUpdates request`. Модули отбивают друг друга по кругу, лог забивается ошибками 409.
2. **Каждое событие достаётся только одному модулю.** Сообщение или нажатие кнопки получает тот, кто первым забрал его из очереди, после чего событие подтверждается (`offset = update.Id + 1`) и второму модулю уже не приходит. Например, нажатие «Выдать доступ» может забрать SeriesNotify, который такой кнопки не знает. Отсюда **кнопки срабатывают через раз**.
3. **`tg_target` - бот для входа.** QR-код и кнопка на экране входа открывают `t.me/<бот>?start=<сессия>`. Подтверждение входа обрабатывает только QRAuth. Если `tg_target` указывает на бот SeriesNotify, команда `/start` с номером сессии уйдёт туда и вход не подтвердится.

**Решение:** создайте в [@BotFather](https://t.me/BotFather) два бота. Один для QRAuth (вход и выдача доступа), другой для SeriesNotify (уведомления).

</details>

**4. Перезапустите Lampac.**

> [!IMPORTANT]
> После включения модуля, а также после добавления или удаления `.cs`-файлов нужен **полный перезапуск** процесса. Дальше правки секции `DenyPage` подхватываются на лету.

<details>
<summary>💡 <b>Нужно ли прописывать <code>tgbot/qr</code> в <code>whitepattern</code>?</b></summary>

<br>

Нет. Модуль сам пропускает свои адреса `/tgbot/qr/*` (QR-вход и фон из постеров) через обработчик `EventListener.Accsdb`. Если `tgbot/qr` у вас уже прописан, ничего не меняйте - это не мешает.

</details>

## 🤖 Что умеет бот

| Команда / кнопка | Кто | Что делает |
| --- | --- | --- |
| `/start` | все | Новому пользователю - кнопка «🔑 Запросить доступ», у кого доступ уже есть - кнопка «🔑 Пароль для входа», админу - панель администратора |
| «🔑 Пароль для входа» | у кого есть доступ | Присылает пароль ещё раз (для ручного ввода, второго устройства и т.п.) |
| «✅ Выдать» / «❌ Отклонить» | админы | Решение по заявке: выдача сразу дописывает `users.json` и присылает пользователю пароль |
| `/users` или «👥 Пользователи» | админы | Список пользователей, карточка каждого, бан и разбан |
| «📊 Статистика» | админы | Сколько всего пользователей, активных и заблокированных |
| «✅ Подтвердить вход» | у кого есть доступ | Появляется после сканирования QR - телевизор входит сам |

Админам приходит уведомление о каждом входе: по QR, через кнопку Telegram и по паролю. Если админ без записи в `users.json` сканирует QR, бот сам заводит ему доступ.

> [!NOTE]
> У доступа нет срока действия - только бан и разбан. Продлений, рассылок и журнала действий нет: модуль сделан минимальным.

<details>
<summary>🔑 <b>Как проходит заявка на доступ</b></summary>

<br>

```
Пользователь: /start → нет доступа → «🔑 Запросить доступ»
        │
        ▼
Бот шлёт каждому из admin_ids карточку с кнопками «✅ Выдать» / «❌ Отклонить»
        │
        ├── Отклонить → пользователю «❌ Отклонено», запись не создаётся
        │
        └── Выдать → UsersRepository.AddUser() дописывает users.json
                      (новый токен; старый доступ этого tg_id, если был, заменяется)
                      │
                      ▼
              Пользователю приходит пароль в личку
```

- Повторная заявка от того же пользователя игнорируется 10 минут (защита от спама кнопкой). Таймер в памяти процесса, обнуляется перезапуском.
- Кнопки «Выдать» / «Отклонить» проверяют `admin_ids` - нажатие не-админом ничего не меняет.
- Если у пользователя уже есть активный доступ, заявка не уходит - бот сразу отвечает, что доступ есть.
- Если заявку подали после сканирования QR, одобрение сразу входит в ту самую сессию на экране - без пароля.

</details>

<details>
<summary>📷 <b>Как работает вход по QR</b></summary>

<br>

```
deny.js:  GET /tgbot/qr/start  → { session }
          строит QR на https://t.me/<bot>?start=qr_<session>
          (кнопка «Войти через Telegram» - ?start=tg_<session>)
        │
        ▼
Пользователь сканирует QR → /start qr_<session> в боте
        │
        ├── нет доступа → «Запросить доступ» (тот же путь, что и заявка)
        │
        └── доступ есть → бот показывает «✅ Подтвердить вход»
                    │
                    ▼
            Нажатие → QrAuthSessions.TryConfirm(session, token)
                    │
                    ▼
deny.js:  опрос GET /tgbot/qr/status?session=... → { status: confirmed, token }
          → вход этим токеном через {localhost}/testaccsdb
```

- Сессия живёт **3 минуты**, хранится в памяти и одноразовая: `confirmed` отдаётся ровно один раз. По истечении страница сама берёт новый QR, без перезагрузки.
- У каждой загрузки страницы своя сессия, поэтому два устройства друг другу не мешают.
- Перезапуск бота обнуляет активные сессии - достаточно отсканировать QR ещё раз.

</details>

<details>
<summary>📄 <b>Формат users.json</b></summary>

<br>

Файл можно править вручную - модуль его читает и точечно дописывает. Пример записи:

```json
{
  "id": "987654321",
  "tg_id": 123456789,
  "group": 1,
  "expires": "2126-01-01T00:00:00Z",
  "comment": "@ivanov / Иван",
  "ban": false
}
```

Модулю важны три поля:

- `id` - токен, он же пароль и то, чем входит экран входа;
- `tg_id` - Telegram ID числом (не username), по нему бот находит запись;
- `ban` - доступ активен, пока `false`.

`expires` модуль не проверяет - это поле только для ядра Lampac.

</details>

<details>
<summary>🔧 <b>Как модуль стыкуется с accsdb и ядром Lampac</b></summary>

<br>

Модуль и ядро Lampac не вызывают друг друга напрямую. Вся связь - общий файл `users.json` и один адрес ядра, `/testaccsdb`.

- **Откуда берётся `id`.** При выдаче доступа `UsersRepository.AddUser()` генерирует токен: 9 случайных байт (`RandomNumberGenerator`) в base64url без паддинга, около 12 символов. Это `id` в `users.json`, пароль, который получает пользователь, и значение, которым входит `deny.js`.
- **Кто отвечает на `/testaccsdb`.** Ядро Lampac (`ApiController.TestAccsdb`). Оно сверяет `uid` / `account_email` со своим списком аккаунтов в памяти. Модуль в это не вмешивается - только заранее кладёт запись в `users.json`.
- **Как ядро узнаёт о новой записи.** Поллер ядра (`Program.cs: UpdateUsersDb`) примерно раз в секунду проверяет время изменения файла и подмешивает новые записи. Поэтому между «Выдать» и возможностью войти бывает задержка до секунды - это нормально.
- **Почему бан - это `ban=true`, а не удаление строки.** Поллер ядра только добавляет и обновляет записи, но не удаляет исчезнувшие. Удалённый из файла пользователь остался бы залогинен до перезапуска. Поэтому бан меняет `ban` в существующей строке - и ядро обрывает доступ на следующем же запросе.
- **QR-вход - не отдельный канал.** Подтверждение в боте просто передаёт `deny.js` тот же `id` из `users.json`, дальше всё идёт через `/testaccsdb`, как при вводе пароля.

Итого: для ядра Lampac записи, созданные ботом, ничем не отличаются от добавленных вручную.

</details>

## 🎬 Фон из постеров

За экраном входа - стена из постеров популярных фильмов, наклонённая как в Netflix. Её готовит сервис `PosterWall` (`services/posterwall.cs`) прямо на сервере, чтобы телевизору оставалось только показать одну готовую картинку.

**Раз в сутки сервис:**

1. **Берёт список фильмов** из TMDB (см. `poster_source`) - до 30 постеров, без взрослого контента.
2. **Скачивает постеры** в `cache/qrauth/posters/`: сначала во временную папку, которая потом целиком подменяет старую, поэтому страница никогда не видит наполовину скачанный набор.
3. **Собирает из них стену** через NetVips - скруглённые углы, поворот на −7°, затемнение. Горизонтальная (сетка 12×6) для ТВ и компьютеров, квадратная (8×6) для телефонов:

| Файл | Размер | Для чего |
| --- | --- | --- |
| `wall-v2-4k.jpg` | 3840×2160, ~1–1,5 MB | 2K/4K мониторы и 4K-телевизоры |
| `wall-v2.jpg` | 1920×1080, ~400–500 KB | Все остальные экраны, включая обычные ТВ |
| `wall-v2-lqip.jpg` | 64×36, ~1 KB | Крошечное превью, встроенное прямо в страницу |
| `wall-v2-glass.jpg` | 320×180, ~7 KB | Размытая копия для «стеклянных» кнопок |
| `wall-v2-sq.jpg` | 2532×2532, ~0,6–0,9 MB | Телефоны (экран до 700 px в ширину), в любой ориентации |
| `wall-v2-sq-lqip.jpg` | 48×48, ~1 KB | Превью телефонной стены |

> [!NOTE]
> NetVips уже входит в Lampac (им пользуется его прокси картинок) - ставить ничего не нужно. Если NetVips недоступен, стена не собирается и экран входа остаётся на обычном тёмном фоне.

**Как это показывает страница:**

- **ТВ, компьютер и телефон** грузят одну картинку, каждый свою. Адрес и превью уже вшиты в страницу, поэтому загрузка начинается сразу: мгновенно видно размытое превью, поверх догружается чёткая стена.
- **«Стеклянные» кнопки** тоже заготовлены заранее: кнопка показывает уже размытый кусок стены ровно под собой. Живое размытие (`backdrop-filter`) в WebView Android TV не работало и нагружало слабые ТВ.
- **Телефоны** получают отдельную квадратную стену 2532×2532: из неё без растягивания вырезается и вертикальный экран, и горизонтальный, так что телефон, повёрнутый уже после открытия страницы, остаётся закрыт стеной. Широкая ТВ-картинка, обрезанная под вертикальный экран, была бы растянутой и мыльной.
- **iPhone в горизонтальном положении.** Пока открыт экран входа, страница добавляет `viewport-fit=cover` в тег `viewport`, поэтому стена доходит до краёв экрана, а кнопки и текст отступают от выреза (`env(safe-area-inset-*)`). Без этого Safari закрашивал полосы под вырез однотонным цветом. «Стекло» на телефоне живое (`backdrop-filter`) - телефоны с ним справляются.

<details>
<summary>⚙️ <b>Технические детали</b></summary>

<br>

- **Откуда постеры.** Сначала через встроенный в Lampac `/tmdb`-прокси (локальным запросом с `lcrqpasswd`, как модуль Catalog). Если сервер не достаёт до TMDB (РФ/РБ без прокси) - через те же зеркала, что и сама Lampa с «Проксировать TMDB» (`apitmdb.cub.red`, `imagetmdb.com` и др.).
- **Наружу открыто только своё.** Неавторизованный посетитель не может ходить в `/tmdb/*` Lampac, поэтому модуль открывает только `/tgbot/qr/posters` и `/tgbot/qr/wall`. Сами постеры наружу не отдаются - они только сырьё для стены.
- **Без расширения в адресе** (`/wall`, а не `/wall.jpg`): `accsdb` отдаёт 404 на `*.jpg` для неавторизованных ещё до того, как модуль успеет их пропустить.
- **Выбор разрешения.** Экран до 700 px в ширину (телефон вертикально) запрашивает `/tgbot/qr/wall?s=m` - квадратную стену. Остальные, включая телефон, открытый горизонтально, - `?s=4k`, если экран шире ~2000 физических пикселей, иначе 1080p. Вариант выбирается один раз при открытии. Если нужного файла нет, сервер отдаёт 1080p.
- **Качество.** Постеры берутся с TMDB в размере `w500` и уменьшаются до плиток 370×556, поворот с бикубической интерполяцией. JPEG прогрессивный, без субдискретизации цвета: 4K - q78, 1080p - q85, телефонная стена - q82.
- **Кэш.** Картинки отдаются с `Cache-Control: max-age=86400`, в адресе есть `?v=<версия набора>` - повторное открытие берёт всё из кэша, новый набор получает новый адрес.
- **Расписание.** Проверка идёт каждые 10 минут (первая - через 15 секунд после старта) и ничего не делает, пока набору меньше суток. После перезапуска уже скачанный набор подхватывается с диска сразу. Сама сборка стены занимает несколько секунд в фоне.
- **Стекло.** `wall-v2-glass.jpg` - это 1080p-стена, размытая на 1,41% ширины, пропущенная через матрицу CSS `saturate(1.6)` и осветлённая ×1,3 - та же цепочка, что у `backdrop-filter` кнопок. На странице она подкладывается под кнопку с учётом её положения на экране.
- **Состояние** видно в ответе `/tgbot/qr/posters`: `{"count":30,"v":…,"wall":true,"state":"ok"}`. Подробности сбоев - в `tgbot.log`.

</details>

## ⚙️ Все настройки

<details>
<summary><b>QRAuthBot</b> - бот</summary>

<br>

| Поле | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `enable` | `bool` | `true` | Выключить бота без удаления файлов (экран входа продолжит работать) |
| `bot_token` | `string` | `""` | Токен от BotFather. Пусто при `enable=true` - предупреждение в консоли, бот не запускается, сервер не падает |
| `users_file_path` | `string` | `"users.json"` | Файл пользователей - тот же, что читает `accsdb` |
| `log_path` | `string` | `"tgbot.log"` | Лог модуля |
| `admin_ids` | `long[]` | `[]` | Кто получает заявки и видит `/users`. Пусто - на заявки бот отвечает «Администратор не настроен» |

</details>

<details>
<summary><b>DenyPage</b> - экран входа</summary>

<br>

| Поле | Тип | Описание |
| --- | --- | --- |
| `tg_target` | `string` | `@username`, `https://t.me/…` или `tg://` - бот для QR и кнопки Telegram. Должен совпадать с ботом из `QRAuthBot` |
| `show_qr` | `bool` | QR показывается, только если `tg_target` задан **и** `show_qr = true` |
| `page_title`, `page_subtitle` | `string` | Заголовок и подзаголовок |
| `step1_text`, `step2_text` | `string` | Строки подсказки под кнопками. Пустая строка не выводится; по умолчанию есть только `step2` (если задан `tg_target`) |
| `qr_subcaption` | `string` | Подпись под QR |
| `tg_button_text` | `string` | Текст кнопки «Войти через Telegram». На телефоне она заменяет QR, в браузере на компьютере стоит под кнопкой пароля, на ТВ её нет |
| `poster_wall` | `bool` | Фон из постеров, по умолчанию `true` - см. [Фон из постеров](#posters). Без постеров остаётся обычный тёмный фон |
| `poster_source` | `string` | Откуда постеры: `trending` (по умолчанию, тренды недели), `popular`, `now_playing`, `top_rated` |

</details>

> [!CAUTION]
> **Docker:** `users_file_path` и `log_path` - пути **внутри контейнера** (обычно `/lampac/...`), а не на хосте. Путь хоста приведёт к тому, что бот будет писать пользователей в файл, которого Lampac не видит.

<details>
<summary><b>Как отключить части модуля</b></summary>

<br>

| Способ | Результат |
| --- | --- |
| `QRAuthBot.enable=false` | Бот не запускается, экран входа работает без QR |
| `DenyPage.show_qr=false` | Экран входа без QR, вход по паролю остаётся |
| `DenyPage.poster_wall=false` | Без фона из постеров, модуль не ходит в TMDB |
| `"enable": false` в `manifest.json` (по умолчанию) | Модуль не загружается вообще (нужен перезапуск) |

</details>

## 🩺 Частые проблемы

<details>
<summary><b>После перезапуска Lampac фон из постеров появляется не сразу</b></summary>

<br>

Lampac кэширует `deny.js` в памяти до 10 минут. Модуль подхватывает уже скачанные постеры сразу при старте, но если набор скачивается впервые (новая установка или смена `poster_source`), первые минуты страница может работать по-старому. Это проходит само.

Проверить состояние: `https://ваш-сервер/tgbot/qr/posters` - должно быть `"wall":true`.

</details>

<details>
<summary><b>Фона из постеров нет совсем</b></summary>

<br>

Посмотрите поле `state` в ответе `/tgbot/qr/posters`:

| `state` | Что значит |
| --- | --- |
| `pending` | Первая загрузка ещё не прошла (идёт через 15 секунд после старта) |
| `tmdb_unreachable` | Ни `/tmdb` Lampac, ни зеркала не ответили - проверьте доступ сервера в интернет |
| `tmdb_empty` | TMDB ответил, но постеров нет |
| `images_failed` | Список получен, но картинки не скачались |
| `disabled` | `poster_wall=false` |

</details>

<details>
<summary><b>Пользователь забанен, но всё ещё смотрит</b></summary>

<br>

Бан срабатывает на следующем запросе к серверу после того, как ядро перечитает `users.json` (примерно раз в секунду). Если запись удалили из файла вручную вместо `ban=true`, ядро её не забудет до перезапуска - банить нужно через `/users` в боте или полем `ban`.

</details>
