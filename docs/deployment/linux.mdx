На Linux Lampac NextGen устанавливается одним скриптом `install.sh`. Скрипт загружает .NET 10 runtime, создает системного пользователя `lampac`, распаковывает последний релиз и регистрирует systemd-сервис. Поддерживаются Debian и Ubuntu на архитектурах amd64 и arm64.

## Команды install.sh

<CodeGroup>

```bash Установка
# Установка последней стабильной версии
curl -fsSL https://raw.githubusercontent.com/lampac-nextgen/lampac/main/install.sh | sudo bash
```

```bash Конкретный тег
curl -fsSL https://raw.githubusercontent.com/lampac-nextgen/lampac/main/install.sh | sudo bash -s -- --tag v1.2.3
```

```bash Обновление
curl -fsSL https://raw.githubusercontent.com/lampac-nextgen/lampac/main/install.sh | sudo bash -s -- --update
```

```bash Обновление на конкретный тег
curl -fsSL https://raw.githubusercontent.com/lampac-nextgen/lampac/main/install.sh | sudo bash -s -- --update --tag v1.2.3
```

```bash Повторная установка той же версии
curl -fsSL https://raw.githubusercontent.com/lampac-nextgen/lampac/main/install.sh | sudo bash -s -- --update --force
```

```bash Проверка обновления без изменений
curl -fsSL https://raw.githubusercontent.com/lampac-nextgen/lampac/main/install.sh | sudo bash -s -- --update --dry-run
```

```bash Пред-релиз
curl -fsSL https://raw.githubusercontent.com/lampac-nextgen/lampac/main/install.sh | sudo bash -s -- --pre-release
```

```bash Удаление
curl -fsSL https://raw.githubusercontent.com/lampac-nextgen/lampac/main/install.sh | sudo bash -s -- --remove
```

```bash Подробный лог при установке
curl -fsSL https://raw.githubusercontent.com/lampac-nextgen/lampac/main/install.sh | sudo bash -s -- --verbose
```

```bash Подробный лог при обновлении
curl -fsSL https://raw.githubusercontent.com/lampac-nextgen/lampac/main/install.sh | sudo bash -s -- --update --verbose
```

```bash Текущая версия
curl -fsSL https://raw.githubusercontent.com/lampac-nextgen/lampac/main/install.sh | sudo bash -s -- --version
```

</CodeGroup>

### Флаги install.sh

| Флаг | Описание |
| --- | --- |
| `--tag <версия>` | Установить или обновить на конкретный тег |
| `--update` | Обновить существующую установку через rsync |
| `--force` | Повторно установить текущую версию без подтверждения |
| `--dry-run` | Показать, что изменится, но не применять |
| `--pre-release` | Установить последний pre-release вместо stable |
| `--no-backup` | Обновить без бэкапа: откатываться будет не на что |
| `--no-health-check` | Не ждать ответа сервиса после обновления |
| `--remove` | Полностью удалить Lampac, пользователя и сервис |
| `--verbose` | Вывести подробный лог для диагностики |
| `--version` | Показать установленную версию |

## Переменные окружения

Вы можете переопределить поведение скрипта через переменные окружения. Указывайте их перед `sudo bash` или экспортируйте заранее.

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `LAMPAC_INSTALL_ROOT` | `/opt/lampac` | Директория установки |
| `LAMPAC_USER` | `lampac` | Системный пользователь |
| `LAMPAC_UID` | `1000` | UID (если занят, выбирается свободный) |
| `LAMPAC_GID` | `1000` | GID (если занят, выбирается свободный) |
| `LAMPAC_PORT` | `9118` | Порт: подсказка после установки и адрес проверки после обновления |
| `LAMPAC_GITHUB_REPO` | `lampac-nextgen/lampac` | GitHub-репозиторий релизов |
| `LAMPAC_DOTNET_ROOT` | `/usr/share/dotnet` | Путь установки .NET |
| `LAMPAC_DOTNET_CHANNEL` | `10.0` | Версия .NET runtime |
| `LAMPAC_BACKUP_DIR` | `/opt/lampac-backups` | Куда `--update` сохраняет бэкапы. По умолчанию — `LAMPAC_INSTALL_ROOT` с суффиксом `-backups` |
| `LAMPAC_BACKUP_KEEP` | `1` | Сколько бэкапов хранить |
| `LAMPAC_HEALTH_URL` | `http://127.0.0.1:9118/version?type=hash` | Адрес проверки запуска после обновления |
| `LAMPAC_HEALTH_TIMEOUT` | `240` | Сколько секунд ждать ответа после обновления |

## Управление сервисом

После установки Lampac работает как systemd-сервис `lampac`. Используйте стандартные команды:

```bash
systemctl status lampac
systemctl restart lampac
journalctl -u lampac -f
```

## Что сохраняется при обновлении

Команда `--update` использует `rsync --delete`, которая удаляет файлы, отсутствующие в новом релизе. Следующие пути защищены от удаления и перезаписи:

| Путь | Описание |
| --- | --- |
| `install.sh` | Сам скрипт установки |
| `init.conf`, `init.yaml` | Конфигурация сервера |
| `mods/` | Пользовательские модули |
| `data/kinoukr.json`, `data/PizdatoeDb.json` | Локальные базы данных |
| `*.db`, `*.db-shm`, `*.db-wal` | SQLite (Sync, SISI, TimeCode) |
| `logs/`, `cache/` | Логи и файловый кеш |
| `TorrServer`, `torrserver/`, `data/ts/` | TorrServer и его данные |
| `.local/`, `.aspnet/`, `.claude/`, `.config/`, `.playwright/` | Домашние директории пользователя |
| `users.json`, `passwd`, `current.conf`, `database/` | Пользовательские данные |
| `wwwroot/` | Пользовательская статика и кеш Lampa UI |
| `plugins/override/` | Переопределения плагинов |
| `module/NextHUB/override/`, `module/Catalog/override/` | Переопределения сайтов NextHUB и Catalog |
| `notifications_date.txt` | Состояние уведомлений |
| `excludes.conf` | Файл дополнительных исключений |
| `version.txt` | Файл хранения установленной версии |

### Дополнительные исключения через excludes.conf

Чтобы защитить свои собственные файлы и папки, создайте `excludes.conf` рядом с `Core.dll` (обычно `/opt/lampac/excludes.conf`). Каждая строка — одно исключение, `#` для комментария. Пути относительны `LAMPAC_INSTALL_ROOT`, для папок используйте trailing slash, поддерживаются glob-паттерны.

```bash
# /opt/lampac/excludes.conf — одно исключение на строку, # — комментарий
my_custom_folder/
config/local.conf
*.custom
```

## Бэкап и откат при обновлении

`--update` защищает от релиза, который не запускается.

1. Перед заменой файлов скрипт копирует приложение в `/opt/lampac-backups/<дата>-<время>_<версия>/`. Исключения те же, что у обновления: конфигурация, базы и кеш в бэкап не попадают и при откате не меняются. По умолчанию хранится один бэкап, более старые удаляются перед созданием нового.
2. После запуска сервиса скрипт ждёт ответа `GET /version?type=hash` до 240 секунд. Lampac открывает порт только после сборки модулей, поэтому ответ означает, что сервис действительно запустился. Успехом считается любой HTTP-ответ ниже 500.
3. Если сервис не ответил или копирование файлов прервалось, скрипт возвращает файлы и `version.txt` из бэкапа, запускает прежнюю версию и завершается с ошибкой.

<Note>
  Адрес проверки скрипт опрашивает ещё до обновления, пока работает текущая версия. Если Lampac слушает другой порт, `listen.ip` или `listen.sock`, адрес не ответит. Тогда скрипт пропустит проверку с предупреждением, чтобы не откатить исправное обновление. Укажите `LAMPAC_PORT` или `LAMPAC_HEALTH_URL`.
</Note>

Если для бэкапа не хватает места, обновление прерывается до остановки сервиса. Освободите место, укажите `LAMPAC_BACKUP_DIR` на другом диске или запустите обновление с `--no-backup`. `--dry-run` показывает путь и размер бэкапа и отвечает ли адрес проверки.

Плейбук Ansible бэкап и проверку запуска не выполняет.

## Установка через Ansible

Плейбук в `ansible/` делает то же, что `install.sh`: пакеты, Google Chrome, ASP.NET Core 10, пользователь `lampac`, релиз с GitHub и systemd. Скопируйте `ansible/inventory/hosts.yml.example` и укажите свой хост. Повторный запуск не скачивает архив, если `version.txt` уже совпадает с нужным тегом. `-e lampac_force=true` синхронизирует ту же версию ещё раз. Исключения `rsync` те же, включая `excludes.conf`.

<CodeGroup>

```bash Установка
ansible-playbook -i ansible/inventory/hosts.yml ansible/site.yml
```

```bash Конкретный тег
ansible-playbook -i ansible/inventory/hosts.yml ansible/site.yml -e lampac_version=v1.2.3
```

```bash Пред-релиз
ansible-playbook -i ansible/inventory/hosts.yml ansible/site.yml -e lampac_prerelease=true
```

```bash Удаление
ansible-playbook -i ansible/inventory/hosts.yml ansible/site.yml -e lampac_state=absent -e lampac_confirm_remove=true
```

</CodeGroup>

`lampac_init_conf` записывается в `init.conf` при каждом запуске. Значения по умолчанию совпадают с `config/example.init.conf`, а `listen.port` берётся из `lampac_port`. `lampac_init_conf: {}` оставляет файл на хосте без изменений. Чтобы записать `init.yaml`, задайте `lampac_init_conf: {}` и mapping в `lampac_init_yaml`. Оба сразу задавать нельзя: Lampac читает тот файл, что новее. `passwd`, `users.json` и `excludes.conf` записываются только когда переменная не пустая.

```yaml
lampac_passwd: "set-this"
lampac_users:
  - id: "user@example.com"
    group: 1
lampac_excludes:
  - "my_custom_folder/"
```
